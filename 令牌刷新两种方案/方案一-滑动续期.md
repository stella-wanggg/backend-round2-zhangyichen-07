# 方案一：滑动续期（现有 `new-token` 方案）

> 如果还没弄懂“access token / refresh token / 刷新”这几个词，先看同目录的 `00-先弄懂令牌刷新.md`，再回来看这篇。

## 1. 现在的代码已经写到哪一步了

我把 `JwtUtil` 和 `Interceptor` 翻了一遍，滑动续期的主体其实已经有了：

```text
JwtUtil
├── generateToken(id, name, role)      生成 token
├── parseToken(token)                  解析 token
└── tokenNearExpiration(token)         剩余时间 < 5 分钟返回 true

Interceptor
├── 从 token 头取令牌
├── 解析出 id / name / role
├── 快过期 → 重新生成 → 放到响应头 new-token
└── 把 id / name / role 放进 request attribute
```

所以方案一**不是重写，而是补几个细节**。

## 2. 原理：快到期时“悄悄换一张卡”

把它想成会员卡：

- 你每次进店，前台看一眼卡的有效期；
- 如果发现还有不到 5 分钟就到期，前台顺手给你一张新卡；
- 你下次用新卡就行，自己不用专门去续；
- 但如果你三个月没来，卡已经过期了，前台也没法给你续，只能重新办卡（重新登录）。

对应到代码：

```text
请求进来
  → 拦截器验 token
  → 还没过期？
      → 剩余 < 5 分钟：生成新 token，放进响应头 new-token
      → 剩余 >= 5 分钟：什么也不做
  → 放行
```

## 3. 对照代码：现在的问题

### 3.1 `JwtUtil` 用平台默认编码取密钥

```java
return Keys.hmacShaKeyFor(jwt.getSecret().getBytes());
```

在不同操作系统/默认编码下，同一串密钥可能得到不同字节。建议明确写 UTF-8：

```java
return Keys.hmacShaKeyFor(jwt.getSecret().getBytes(StandardCharsets.UTF_8));
```

### 3.2 `tokenNearExpiration` 没有判断“是否已经过期”

现在写的是：

```java
if (expiration.getTime() - now.getTime() < 5 * 60 * 1000) {
    return true;
}
```

如果 token 已经过期，差值是负数，也会返回 `true`。虽然在拦截器里 `parseToken` 会先拦掉过期 token，但这个方法单独看是有歧义的。建议加一个 `remaining > 0`：

```java
long remaining = expiration.getTime() - now.getTime();
return remaining > 0 && remaining < 5 * 60 * 1000L;
```

### 3.3 `claims.get("role").toString()` 可能空指针

旧 token 里没有 `role` claim 时，`get("role")` 返回 `null`，再 `.toString()` 就 NPE 了。建议：

```java
String role = claims.get("role", String.class);
if (role == null) {
    role = "user"; // 旧 token 先按普通用户处理，管理员重新登录
}
```

### 3.4 浏览器跨域读不到 `new-token`

`new-token` 是响应头。如果前端和接口不同源，浏览器默认不把自定义响应头暴露给 JS，需要加：

```java
response.setHeader("Access-Control-Expose-Headers", "new-token");
```

### 3.5 只认 `token` 头

现在的拦截器只读 `request.getHeader("token")`。如果以后前端想用 `Authorization: Bearer xxx`，可以加一个兼容分支。

### 3.6 所有 token 异常都返回 401「令牌解析失败」

这样前端没法区分是“过期了”还是“token 被改坏了”。可以单独捕获 `ExpiredJwtException`，返回一个业务码 `40101`。方案一没有 `/refresh`，前端看到 `40101` 就回登录页；以后接方案二时，同一个码可以直接触发刷新。

### 3.7 这套方案本身的限制

- 只能在 token **还没过期**时续；
- 用户如果超过有效期没访问，还是要重新登录；
- 旧 token 在过期前一直有效，不能主动作废；
- 做不到“关掉页面几天后再打开还免登录”。

## 4. 完整代码

### 4.1 `application.yaml`

正式环境保持 2 小时：

```yaml
jwt:
  secret: ${JWT_SECRET:zhangyichen0205abcdefghijklmnopqrstuywxz}
  expiration: 7200000   # 2 小时
```

测试滑动续期时，建议临时改短，不然要等两个小时：

```yaml
jwt:
  expiration: 360000    # 6 分钟，剩余 5 分钟时就会触发续期
```

> `tokenNearExpiration` 的阈值是 5 分钟，所以 `expiration` 必须大于 5 分钟，否则 token 一签发就已经“快过期”了。

### 4.2 `JwtUtil.java`

```java
package com.example.util;

import com.example.config.yaml.jwtYaml;
import io.jsonwebtoken.Claims;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.SignatureAlgorithm;
import io.jsonwebtoken.security.Keys;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

import javax.crypto.SecretKey;
import java.nio.charset.StandardCharsets;
import java.util.Date;

@Component
public class JwtUtil {

    @Autowired
    private jwtYaml jwt;

    private SecretKey getSecretKey() {
        return Keys.hmacShaKeyFor(
                jwt.getSecret().getBytes(StandardCharsets.UTF_8));
    }

    public String generateToken(Integer id, String name, String role) {
        Date now = new Date();
        Date exp = new Date(now.getTime() + jwt.getExpiration());

        return Jwts.builder()
                .setSubject(id.toString())
                .claim("name", name)
                .claim("role", role)
                .setIssuedAt(now)
                .setExpiration(exp)
                .signWith(getSecretKey(), SignatureAlgorithm.HS256)
                .compact();
    }

    public Claims parseToken(String token) {
        return Jwts.parserBuilder()
                .setSigningKey(getSecretKey())
                .build()
                .parseClaimsJws(token)
                .getBody();
    }

    public boolean tokenNearExpiration(String token) {
        Claims claims = parseToken(token);
        long remaining = claims.getExpiration().getTime()
                - System.currentTimeMillis();
        return remaining > 0 && remaining < 5 * 60 * 1000L;
    }
}
```

### 4.3 `Interceptor.java`

```java
package com.example.interception;

import com.alibaba.fastjson.JSONObject;
import com.example.result.Result;
import com.example.util.JwtUtil;
import io.jsonwebtoken.Claims;
import io.jsonwebtoken.ExpiredJwtException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import lombok.extern.slf4j.Slf4j;
import org.jspecify.annotations.Nullable;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.http.HttpMethod;
import org.springframework.stereotype.Component;
import org.springframework.util.StringUtils;
import org.springframework.web.servlet.HandlerInterceptor;
import org.springframework.web.servlet.ModelAndView;

import java.io.IOException;

@Slf4j
@Component
public class Interceptor implements HandlerInterceptor {

    @Autowired
    private JwtUtil jwtUtil;

    @Override
    public boolean preHandle(HttpServletRequest request,
                             HttpServletResponse response,
                             Object handler) throws Exception {

        log.info("请求的url:{}", request.getRequestURL().toString());

        // 浏览器跨域预检请求直接放行
        if (HttpMethod.OPTIONS.matches(request.getMethod())) {
            return true;
        }

        // 先读 token 头，再兼容 Authorization: Bearer
        String jwt = request.getHeader("token");
        if (!StringUtils.hasText(jwt)) {
            String authorization = request.getHeader("Authorization");
            if (StringUtils.hasText(authorization)
                    && authorization.startsWith("Bearer ")) {
                jwt = authorization.substring(7);
            }
        }

        if (!StringUtils.hasText(jwt)) {
            writeError(response, 401, "未登录,令牌不存在");
            return false;
        }

        try {
            Claims claims = jwtUtil.parseToken(jwt);

            Integer userId = Integer.parseInt(claims.getSubject());
            String name = claims.get("name", String.class);
            String role = claims.get("role", String.class);
            if (role == null) {
                // 旧 token 没有 role，先按普通用户处理；管理员重新登录即可
                role = "user";
            }

            // 后面的 Controller / Service 都从这里取当前用户
            request.setAttribute("id", userId);
            request.setAttribute("name", name);
            request.setAttribute("role", role);

            // 滑动续期：快过期但还没过期
            if (jwtUtil.tokenNearExpiration(jwt)) {
                String newToken = jwtUtil.generateToken(userId, name, role);
                response.setHeader("new-token", newToken);
                // 跨域时让浏览器能读到这个响应头
                response.setHeader("Access-Control-Expose-Headers", "new-token");
                log.info("token 快过期，已签发 new-token");
            }

            return true;

        } catch (ExpiredJwtException e) {
            // 已经过期：方案一里让前端回登录页；接方案二后可以改成触发 /refresh
            writeError(response, 40101, "登录已过期,请重新登录");
            return false;

        } catch (Exception e) {
            log.warn("令牌解析失败", e);
            writeError(response, 401, "令牌解析失败");
            return false;
        }
    }

    private void writeError(HttpServletResponse response,
                            int code,
                            String message) throws IOException {
        response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
        response.setContentType("application/json;charset=utf-8");
        response.setCharacterEncoding("UTF-8");
        Result error = Result.error(code, message);
        response.getWriter().write(JSONObject.toJSONString(error));
    }

    @Override
    public void postHandle(HttpServletRequest request,
                           HttpServletResponse response,
                           Object handler,
                           @Nullable ModelAndView modelAndView) throws Exception {
        HandlerInterceptor.super.postHandle(request, response, handler, modelAndView);
    }

    @Override
    public void afterCompletion(HttpServletRequest request,
                                HttpServletResponse response,
                                Object handler,
                                @Nullable Exception ex) throws Exception {
        HandlerInterceptor.super.afterCompletion(request, response, handler, ex);
    }
}
```

### 4.5 前端怎么接

```js
async function request(url, options = {}) {
  const res = await fetch(url, {
    ...options,
    headers: {
      ...(options.headers || {}),
      token: localStorage.getItem("token") || ""
    }
  });

  // 快过期时服务端给的新 token
  const newToken = res.headers.get("new-token");
  if (newToken) {
    localStorage.setItem("token", newToken);
  }

  if (res.status === 401) {
    // 方案一：直接回登录页
    location.href = "/login.html";
  }

  return res;
}
```

### 4.6 Postman 测试时怎么不用手动粘

没有前端的时候，Postman 就是“客户端”。你手动复制 `new-token`，本质上是在扮演客户端做“保存新 token”这一步。纯后端开发/测试阶段这是正常的；等有了前端，这一步应该由前端拦截器自动完成，用户不需要知道 token 的存在。

在 Postman 里，每个请求都有一个 **Tests** 标签页，响应回来后可以自动执行一段脚本。把下面这段放进去：

```js
const newToken = pm.response.headers.get("new-token");
if (newToken) {
    pm.collectionVariables.set("token", newToken);
    console.log("token 已更新");
}
```

然后把请求头写成变量：

```http
token: {{token}}
```

这样：

1. 登录请求把返回的 token 存进集合变量；
2. 之后每次请求如果响应头里有 `new-token`，脚本会自动覆盖变量；
3. 下一次请求直接用新 token，不需要手动复制粘贴。

登录请求的 Tests 可以写：

```js
const body = pm.response.json();
if (body.code === 200) {
    pm.collectionVariables.set("token", body.data);
}
```

> 手动复制只适合临时调试。Postman 的 Tests 脚本、前端拦截器，都是在替用户做这一步；真正的产品不应该让用户看到 token，更不应该让用户手动粘。

## 5. 测试步骤

1. 把 `application.yaml` 的 `expiration` 临时改成 `360000`（6 分钟），重启。
2. 登录拿 token。
3. 等 1 分钟（剩余时间进入 5 分钟内）。
4. 调任意受保护接口，比如 `/showbyid/{id}`。
5. 看响应头里有没有 `new-token`。
6. 用 `new-token` 替换旧 token 再请求，应该正常。

用 curl 看响应头：

```bash
# 登录，取 token
TOKEN=$(curl -s -X POST http://localhost:8080/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"123456"}' \
  | python -c "import sys,json; print(json.load(sys.stdin)['data'])")

# 带 token 请求，-i 显示响应头
curl -i http://localhost:8080/showbyid/1 -H "token: $TOKEN"
```

响应里会多出：

```http
new-token: eyJhbGciOiJIUzI1NiJ9...
Access-Control-Expose-Headers: new-token
```

再把 `expiration` 改成 `60000`（1 分钟），等过期后请求，会得到：

```json
{
  "code": 40101,
  "message": "登录已过期,请重新登录",
  "data": null
}
```

## 6. 优缺点

| 优点 | 缺点 |
|---|---|
| 不需要新表、新接口 | 只能续“还没过期”的 token |
| 改动小，现有代码基本能复用 | 过期后必须重新登录 |
| 活跃用户完全无感 | 做不到长期免登录 |
| 实现简单，容易测试 | 旧 token 在过期前无法撤销 |

## 7. 什么时候选它

- 作业只要求“JWT 登录凭证 + 活跃续期”；
- 时间紧，不想动数据库；
- 先跑通 token 流程，再考虑加 refresh token。

如果需要“access token 过期后还能自动换新”和“关闭页面几天后再打开免登录”，继续看方案二。
